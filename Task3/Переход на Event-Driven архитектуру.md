# Задание 3. Переход на Event-Driven архитектуру

### Список проблем и рисков связанных с планируемым ростом нагрузки
1. Высокая связность текущей системы с внешними API страховых компаний (недоступность одно из API приводит к получению неполных данных)
2. Высокая связность сервиса интеграции ins-product-aggregator с core-app и ins-comp-settlement (любое увеличение нагрузки на один из сервисов необходимо учитывать в других)
3. Низкая отказаустойчивость (недоступность внешнего API или долгий ответ приводит к ошибке получения данных о страховых продуктах)
4. Низкая гибкость в разработке (добавление новых API привело к необходимости доработок в core-app и ins-comp-settlement)

### Пояснения к полученному решению
Так как теперь ins-product-aggregator имеет свою базу где хранить текущее состояние страховых продуктов и тарифов (для возможности вычисления разницы и публикации этой разницы в очередь), то имеет смысл в его реализации использовать паттерн Transactional Outbox.
